Adrobot

Редактор существующих кампаний Keitaro. Документ описывает пользовательские сценарии, модель PostgreSQL, запросы и расположение кода.

Что сделано

  • ReactКампании, потоки и журнал
  • Nginx → FastAPIAPI, проверка запросов и операции редактора
  • PostgreSQLЧерновики, снимки, архив и журнал
  • KeitaroКампании, потоки, каталог и опубликованные доли
  1. Список кампаний с пагинацией и фильтрацией загруженной страницы по имени, алиасу или ID. Точный ID открывает кампанию через отдельный запрос в Keitaro.
  2. Редактор показывает потоки со схемой landings, в том числе пустые. В такой поток можно добавить первый оффер. Над списком расположены обновление из Keitaro, ссылка в админку, каталог офферов и история.
  3. Оффер выбирают в раскрывающемся списке с поиском по ID. Привязанные записи помечены зелёным статусом «Назначен». Открепление подтверждается в диалоге. Затем строка уходит в конец списка с долей 0% и действием «Вернуть».
  4. Добавление, открепление, возврат и снятие закрепления пересчитывают доли. Закреплённые доли сохраняются. Целочисленный остаток распределяется по порядку. Для активных офферов с корректным составом сумма долей равна 100%.
  5. Черновик выделен цветом. Его можно сбросить или опубликовать. После успешной публикации изменения попадают в журнал кампании. Таблица истории поддерживает фильтры, сортировку по времени и курсорную пагинацию.
  6. Интерфейс использует Manrope и Golos Text, светлую и тёмную темы. Разделы организованы по FSD, состояние экранов хранится в Redux Toolkit, ответы API кеширует TanStack Query.

Зачем история. Журнал показывает, когда менялись офферы и доли. Время этих событий можно сопоставить с кликами из отчётов Keitaro. Записи появляются с новых подтверждённых публикаций через Adrobot.

Таблицы и связи

stream_edits

Одна запись на поток кампании.

campaign_id, stream_id · integer
Составной первичный ключ из идентификаторов Keitaro.
published · jsonb
Сохранённый состав с именами, долями, закреплениями и архивными записями.
remote_offers · jsonb
Нормализованный снимок Keitaro для обнаружения конфликтов.
draft · jsonb, nullable
Изменения до публикации. NULL означает отсутствие черновика.
revision · integer
Текущая версия. Действие со старой версией получает 409.
conflicted · boolean
Признак расхождения с актуальным составом Keitaro.

stream_publications

Одна запись на подтверждённую публикацию с изменениями.

id · bigint identity
Первичный ключ и курсор пагинации.
campaign_id, stream_id · integer
Идентификаторы кампании и потока из Keitaro.
stream_name · text
Название потока на момент публикации.
published_at · timestamptz
Время записи подтверждённого изменения.
changes · jsonb
Изменённые офферы. Для каждого записаны ID, имя, действия и состояния before/after с долей и закреплением.

Связь 1:N. Запись редактора и записи журнала связаны логически по паре (campaign_id, stream_id). Внешнего ключа между таблицами нет. Составной индекс ix_stream_publications_campaign_id_id поддерживает выборку по кампании и переход по курсору id в обе стороны.

Каталоги кампаний и офферов живут в Keitaro. В PostgreSQL также есть служебная таблица alembic_version. Транзакционная блокировка PostgreSQL упорядочивает операции редактора в рамках кампании. Публикация в Keitaro подтверждается повторным чтением. Если ответ на запись потерялся, сервис сравнивает фактический состав с ожидаемым.

API и назначение запросов

Adrobot · /api/v1

ЗапросЗа что отвечает
GET /campaignsСтраница кампаний. Принимает limit (50 по умолчанию, максимум 100) и offset.
GET /campaigns/{campaign_id}Открывает кампанию по ID и возвращает ссылку в админку Keitaro.
GET /offersКаталог Keitaro для селекта и окна «Все офферы».
GET /offers/{offer_id}Один оффер по ID.
GET /campaigns/{campaign_id}/streamsЗагружает потоки и сверяет их с PostgreSQL. Возвращает состав, состояние и версию каждого потока.
POST …/streams/{stream_id}/draftПринимает revision, offer_id и действие add, remove, restore или toggle_pin. Сохраняет черновик.
POST …/streams/{stream_id}/cancelПринимает revision, сбрасывает черновик и получает актуальное состояние Keitaro.
POST …/streams/{stream_id}/publishПринимает revision, публикует и проверяет состав, фиксирует изменение в журнале.
GET /campaigns/{campaign_id}/historyИстория и next_cursor. Фильтры stream, offer, action, from_date, until_date. Порядок задаётся descending, страницы — limit и cursor.
GET /health/liveПроверка процесса FastAPI.
GET /health/readyПроверка соединения с PostgreSQL.

Многоточие означает префикс /campaigns/{campaign_id}. Конфликты версий и данных возвращают 409, нарушения правил редактирования и формата — 422.

Keitaro · /admin_api/v1

ЗапросЗа что отвечает
GET /campaigns, GET /campaigns/{id}Список и карточка. При чтении истории карточка подтверждает доступ и даёт текущее имя кампании.
GET /campaigns/{id}/streamsСписок потоков и привязок для сверки.
GET /offers, GET /offers/{id}Каталог, имена и проверка статуса оффера при добавлении или возврате.
GET /streams/{id}Текущий состав перед операцией и проверка результата записи.
PUT /streams/{id}Записывает полный состав с offer_id, share и state. Откреплённые записи исключаются.

Пример публикации с условным ID. share передаётся целым процентом.

{"schema":"landings","offers":[{"offer_id":123,"share":100,"state":"active"}]}

Заголовок Api-Key добавляет только FastAPI. Клиент Keitaro проверяет формат ответа, обрабатывает ошибки доступа, таймауты и лимиты. При сетевой ошибке запрос чтения повторяется один раз.

Запуск и проверка

Создайте локальный .env по образцу .env.example и укажите адрес и ключ Keitaro. Сервис migrate применяет Alembic до запуска API. Nginx отдаёт фронтенд и проксирует /api/.

docker compose up --build -d --wait
docker compose exec api alembic current
docker compose --profile test run --rm --build tests

Кампании · Swagger · Готовность · Keitaro Admin API

Рабочий Docker Compose обращается к реальному Keitaro. Интеграционные тесты используют отдельную БД. Они проверяют сверку, ошибки и подтверждение публикации, черновики, параллельные правки, расчёт долей, фильтрацию и пагинацию истории.
